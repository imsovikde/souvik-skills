# Naming

This repository is named **Souvik Skills**.

The GitHub repository name is `souvik-skills`, under the owner `imsovikde`. The NPM package name is `@imsovikde/skills`.

## Why This Name

`Souvik Skills` is personal, direct, and durable. It clearly identifies the creator while keeping the category obvious to developers. It follows the same pattern as strong founder or organization skill catalogs: the brand name carries trust, and `skills` explains the product.

## Approved Names

| Surface | Name |
| --- | --- |
| Brand | Souvik Skills |
| GitHub repository | `souvik-skills` |
| GitHub path | `imsovikde/souvik-skills` |
| NPM package | `@imsovikde/skills` |
| CLI binary | `souvik-skills` |

## Naming Rules For Future Skills

1. Use lowercase letters, numbers, and hyphens only.
2. Keep the folder name, `SKILL.md` frontmatter `name`, installer name, and documentation name identical.
3. Prefer short action or craft names over long descriptive titles.
4. Avoid generic names that are too broad, certification-like, or hard to remember.
5. Choose names that can be said aloud, typed once, and remembered after one hearing.
6. Do not use names that imply legal, security, or marketplace certification unless the repository actually provides that certification.
7. Check obvious conflicts on GitHub and NPM before publishing.

## Skill Name Purpose

A skill name should answer three questions quickly:

- What kind of work does this skill help with?
- Can a developer remember and install it from a command line?
- Can the name grow if the skill becomes more capable?

If a name cannot work in `npx @imsovikde/skills install <skill-name>`, it is not ready.
