# Vector Quantization Mathematics & Sub-Pixel Geometry Preservation

## 1. Problem Formulation

In a vector PDF content stream generated by Chromium/Skia, text glyphs are defined as parametric cubic Bézier curves:
$$\mathbf{B}(t) = (1-t)^3 \mathbf{P}_0 + 3(1-t)^2 t \mathbf{P}_1 + 3(1-t) t^2 \mathbf{P}_2 + t^3 \mathbf{P}_3, \quad t \in [0, 1]$$

where $\mathbf{P}_0, \mathbf{P}_1, \mathbf{P}_2, \mathbf{P}_3 \in \mathbb{R}^2$ represent the curve endpoints and control handles in PDF point units ($1\text{ pt} = \frac{1}{72}\text{ inch}$).

When printed through Chromium, coordinate values are output as ASCII floats with 6 fractional digits:
$$\mathbf{P} = (x, y), \quad x = x_i + \sum_{k=1}^6 d_k 10^{-k}$$

The ASCII representation requires 8–10 bytes per float coordinate, leading to massive stream file size expansion.

## 2. Why Integer Rounding Fails (Catastrophic Serif Collapse)

A naive approach to vector stream compression is rounding coordinates to the nearest integer:
$$\mathbf{P}_{\text{int}} = (\lfloor x + 0.5 \rfloor, \lfloor y + 0.5 \rfloor)$$

### The Counter-Loop Singularity
For a standard 10pt font, thin counter-loops (such as the interior loops of characters `0`, `8`, `o`, `e`, `a`) and fine serifs have stroke thicknesses $w \le 0.35\text{ pt}$.
If two opposite path boundaries lie at $x_1 = 12.35$ and $x_2 = 12.65$ ($w = 0.30\text{ pt}$):
- $\lfloor 12.35 + 0.5 \rfloor = 12$
- $\lfloor 12.65 + 0.5 \rfloor = 13$
This increases stroke thickness from $0.30\text{ pt}$ to $1.0\text{ pt}$, a $233\%$ distortion that fills closed loops and turns hollow characters into solid blobs.
Conversely, if $x_1 = 12.55$ and $x_2 = 12.85$:
- Both round to $13$, collapsing the stroke width to $0$, causing characters to disappear or tear.

Hence, **integer rounding is strictly prohibited** for legal and compliance documents.

## 3. Sub-Pixel Quantization Grids

To preserve curve geometry, coordinate quantization must remain within the sub-pixel antialiasing threshold of standard rasterizers ($< 0.05\text{ pt}$).

### Scheme A: `r2dec` (Centipoint Precision, 0.01 pt)
Quantization operator:
$$Q_{0.01}(x) = \frac{\lfloor 100x + 0.5 \rfloor}{100}$$

- Maximum displacement: $\epsilon_{\max} = 0.005\text{ pt} \approx 1.76\text{ \mu m}$.
- Rendering Difference: For 1200 DPI output, 1 dot $= 0.06\text{ pt}$. The maximum displacement is less than $1/12\text{th}$ of a device pixel.
- Visual Quality: Mathematically indistinguishable from the original stream ($\text{PSNR} = \infty\text{ dB}$, $\text{SSIM} = 1.000$).
- Applied unconditionally to Page 1 of legal petitions, master complaints, and signature/seal pages.

### Scheme B: `r025` (Quarter-Point Precision, 0.25 pt)
Quantization operator:
$$Q_{0.25}(x) = \frac{\lfloor 4x + 0.5 \rfloor}{4}$$

- Possible values: $k, k + 0.25, k + 0.5, k + 0.75$.
- Maximum displacement: $\epsilon_{\max} = 0.125\text{ pt}$.
- Stream Savings: Eliminates 3–4 ASCII characters per coordinate token.
- Stability: Preserves glyph legibility and stroke separation for body text down to 6pt.

### Scheme C: `r05` (Half-Point Precision, 0.5 pt)
Quantization operator:
$$Q_{0.5}(x) = \frac{\lfloor 2x + 0.5 \rfloor}{2}$$

- Maximum displacement: $\epsilon_{\max} = 0.25\text{ pt}$.
- Stream Savings: Maximum ASCII reduction.
- Applied to large secondary evidentiary tables, dense transaction appendices, and multi-page bank statements when budget ceilings are restrictive.
